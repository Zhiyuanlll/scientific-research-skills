# 来源、去重与增量维护

## 来源定位

来源登记保存在目标库，使用稳定标识连接笔记与原件。记录实际读取的位置、版本或修改时间以及定位锚点，例如 Markdown 标题、PDF 页码、代码函数、数据行/字段、可访问聊天的日期与消息位置。按任务需要记录文件哈希，避免把最新路径等同于同一版本。

来源条目可采用：

```yaml
---
type: source
status: reviewed
source_id: S-001
updated: 2026-01-01
---
```

正文记录标题、作者或所属项目、原始位置、实际阅读范围、版本、可用性及关联笔记。日期为示例，不能原样当作实际完成日期。代码定位说明“实现可检查”；数值结论另需结果文件、参数、运行记录和统计范围。聊天可提供研究意图，但不能单独证明实验已完成。不可访问来源标记为缺失或待访问，不虚构已读内容。

概念或方向笔记可选用以下简单属性，已有 schema 优先：

```yaml
---
type: concept
status: reviewed
aliases:
  - Example alias
sources:
  - S-001
updated: 2026-01-01
---
```

`type` 可按目标库扩展；常见角色为 `concept`、`direction`、`method`、`literature`、`project`、`log`、`source`、`index`。`status` 描述整理状态，如 `draft`、`reviewed`、`needs-evidence`、`historical`，不代表科学真理的等级。科学主张仍需在正文说明证据与范围。`sources` 使用来源标识或可定位引用；文末加具体锚点，避免用一个笼统来源包办全部结论。

## 证据状态

在自然行文或证据表中区分：直接观察、模型导出、解释性假设、未执行方案、未知。无需每句机械贴标签，但读者必须能够辨别。对于修正或相反结果，说明新旧条件与证据；不要悄悄把旧结论改成没有历史的新共识。

标准背景补充使用已核实的公开文献、教材或官方技术文档。若当前任务无法联网且没有相关来源，可以保留清楚标注的待核验概念草稿，不能给不确定内容配虚构书目。不要把公开背景写成用户自己的发现。

## 去重与改动

先比较问题、定义、适用条件、证据来源和版本，再决定复用、合并或并列。完全重复候选也需检查用户批注和链接；语义相似候选更需人工判断。不同材料、温度、尺度、假设、符号约定与验证范围不能因标题相同而消失。

维护流程：

1. 读取本地规则、上次维护记录和来源变化；优先哈希或版本差异，不能仅凭修改时间断定新结论。
2. 记录拟编辑文件的原始哈希，完成有来源的增量草稿；新增文件先检查同名、别名及语义相近笔记。
3. 保存原文件备份及相对路径清单；检查当前哈希仍与所读版本一致，再合并。冲突则重新读取并保留双方修改。
4. 校验来源、链接、导航和覆盖；保存简短变更记录，包含合并依据、缺口及未改动原因。

备份可按本地约定保留；将其放在 vault 外或明确排除，避免重复检索。脚本审计前后只读取 vault，报告写入显式指定的 vault 外路径。为不熟悉的已有库运行严格属性检查前，先判断其是否采用上述属性，不能把兼容性提示当作批量改写理由。

## 只读审计脚本的边界

`audit_vault.py` 检查结构而非科学内容。它忽略代码围栏和行内代码中的链接示例；支持常用 wiki 路径、显示别名、笔记别名、`.md` 扩展名、标题及块引用，以及括号/百分号编码的常用 Markdown 文件路径。歧义引用需要人工判定。HTML 链接、复杂嵌套 Markdown、插件特有 URI 与所有 Obsidian 标题规范不保证完整覆盖。

安装 PyYAML 时安全解析完整 YAML；否则只检查 frontmatter 闭合及保守提取常用标量/列表，并将 YAML 深层校验标记为未执行。复杂属性应在有 PyYAML 的环境重审，脚本不安装依赖。外链只报告未联网；不存在“未联网但已确认有效”的结论。完全重复检测是候选提示，不删除文件，也不能替代语义去重和方向覆盖审阅。
