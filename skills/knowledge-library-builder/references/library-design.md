# 总库设计与方向深化

## 层次与拆分原则

总库可有首页、领域地图、公共概念、研究方向、方法、文献、项目、日志、附件及来源维护，但这只是候选角色。沿用已有结构，不为对称而创建无内容目录。不同方向通常放在同一个 vault，便于共用概念；只有访问权限、共享范围或用户工作方式要求隔离时才分成独立 vault。

方向需要一个可以独立陈述的问题，例如“哪些机制决定某类缺陷的运动速率”。“某软件”通常是方法；若目标确为软件学习库，也可按用户目标建立。方向相关不等于重复：基础力学可以共用，各方向保留特有边界、测量方法、尺度和证据。

拆分专题时考虑：是否有独立可检验问题、是否包含足够内容、是否值得单独复用。两个标题不同但只是改写同一定义时归入同一主笔记；同一标题下存在不同机制和适用条件时可按问题拆分。短内容可以保留在方向综述中，不强行制作原子笔记。

## 方向深化的内容验收

每个方向整体应回答以下问题，允许按资料密度合并或拆分笔记：

1. **问题与边界**：研究对象、尺度、输入、输出以及何时适用。
2. **理论与机制**：核心定义、必要推导或量纲关系、竞争机制、关键假设。公式解释符号与适用条件，不能仅贴公式。
3. **方法与观测**：如何建立模型、提取可观测量、比较条件、收敛和验证。说明数据处理规则及可能偏差。
4. **证据与结论**：来源支持了什么；哪些是文献共识、哪些是用户的结果；矛盾证据和未通过的检验如何影响解释。
5. **关联与缺口**：与公共理论和其他方向的关系、尚未知的机制，以及未执行的研究设想。

方向入口负责组织以上内容，不能把全部实质内容外包给“请参见”链接。专题笔记至少有一个独立可用的解释、推导、方法或证据归纳；只有问题列表的内容应明确列为待研究问题，而不充当已完成的知识。

## 选择深度

- **入门**：概念含义、典型例子、常见参数、基本边界和阅读顺序。
- **研究**：机制对照、定量关系、方法选择、证据强弱和可检验问题。
- **深入**：推导细节、离散化或参数化约定、误差来源、版本差异和反例。

一个方向可以混合深度；记录用户目标与当前证据覆盖，不给用户推断能力等级。资料密集方向可以深入，资料薄弱方向优先完成有来源的基线综述并标出缺口。

## 内容边界

知识笔记直接解释对象与证据。运行进度和下一步安排留在日志或项目任务中。维护报告记录编辑过程，避免混入正式知识正文。推导、失败检验和未知范围属于知识内容，不能因“凝练”而删除。

文献笔记围绕原论文的主张与限制；项目笔记围绕用户工作及其产物；概念笔记围绕可复用定义和理论。三者通过链接建立关系，无须全文复制。知识图只展示有意义的依赖或关系，不以连线密度衡量质量。
