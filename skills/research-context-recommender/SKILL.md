# 科研上下文文献推荐

把当前科研问题转成可检索的问题，为每篇推荐说明实际用途，并保存可追溯的状态、文献和反馈。调用现有 `nature-academic-search` 完成文献发现与核实；本 Skill 负责上下文衔接，不重写检索引擎。

调度器决定运行时间和交付聊天；本 Skill 不创建、移动或修改定时任务。研究方向、聊天 ID、检索数量和时间范围来自运行配置与最新用户要求，不固化为技能规则。默认中文交付。

## 读取配置和历史

使用调用方提供的 `runtime_dir`；未指定时，使用当前项目下的 `文献推荐记录/`。读取其中的 `config.json` 和 `records.json`。不存在时可在已授权的项目目录初始化，不能覆盖已有记录。配置与记录格式、命令示例见 [记录与配置](references/records.md)，首次持久化前读取该文件。

运行记录助手取得压缩上下文：

```text
python3 <skill_dir>/scripts/record_store.py --store <runtime_dir>/records.json context
```

路径参数用实际绝对路径替换。`context` 返回最新研究状态、反馈、历史文献标识和最近运行概况；原始事件保留在记录文件中，可按运行 ID 读取完整报告。没有历史就是尚未建立覆盖，不能宣称已排除所有过去读过的文章。

## 1. 更新有来源的研究状态

- 读取配置中的周总结聊天，再用 `list_threads` 发现最近研究活动，按需用 `read_thread` 读取实际讨论。默认先看近 7 天，证据不足可回看 14 天或最近可核实记录。标题、摘要和修改时间用于寻找材料，不能单独证明进展。
- 同时读取推荐聊天中尚未记录的用户反馈；必要时读取明确关联、允许访问的科研材料。跨聊天读取已有证据即可，不向其他聊天发消息。
- 区分用户报告的结果、可核查的执行/材料结果、助手建议和推断。计划不能转写成已完成成果；自动周报中的结论需保留其底层来源，来源不可读取时标为转述或待核实。工具建设与科学结论分别记录。
- 每个活跃项目保存稳定的项目/问题 ID、当前问题、已有结果、卡点、优先级、来源及最近核实日期。无新证据时保留旧核实日期并注明信息年龄；发现矛盾时保留双方证据，不能自行消除冲突。研究方向不限于初始发现入口。
- 保存一份新的 `state` 事件，保留旧快照。上下文来源无法访问时说明实际覆盖范围；可用已核实状态继续，不捏造最新进展。

### 按领域分别判断研究深度

为本次涉及的每个领域保存独立的 `domain_profile`，将背景、已经掌握的内容、待补知识和当前研究阶段分别记录。先读取配置中的用户自述背景与历史状态，再结合用户明确反馈及有来源的实际工作判断。一个人在熟悉的力学领域深入研究，同时刚进入另一个领域是正常情况，不能使用统一的“入门/进阶”标签。领域细分问题的熟悉程度也可能不同。

阶段使用下表，并保留判断依据、原始日期和不确定性：

| 阶段 | 推荐重点 |
|---|---|
| `entry`：刚进入领域 | 入门综述、概念和分类、代表性案例，以及与已有背景的连接 |
| `orienting`：已有基础、正在选问题 | 专题综述、代表性原始论文、研究路线比较与限制 |
| `problem_driven`：明确问题、开展研究 | 理论、具体方法、参数确定、验证与可复现工作 |
| `results`：形成结果或论文 | 最接近的已有研究、反例、适用边界、争议与最新进展 |
| `unknown`：证据不足 | 标明阶段待确认，按可核实的前置知识安排必要基础材料与问题文献 |

优先采用用户最新明确自述；依据实际讨论或材料作出的阶段判断标为推断。聊天次数、论文推送次数、未反馈及未见读后记录，都不能证明已经掌握或升级阶段。熟悉的基础可跳过，必要的领域新概念仍需补足；避免反复推通用综述，但不能把“曾推送”当作“已读懂”。

刚进入领域时，可以在核心清单中安排约 2–3 篇综述、2–4 篇代表性论文、1–3 篇衔接已有背景的理论/方法文章；这是按需要调整的阅读组合示例，不是每个领域固定占额。随实际进展逐步转向具体问题。个人领域背景及其来源保存在运行配置/状态中，不写死在本 Skill。

## 2. 把问题和反馈转成检索重点

默认选择 1–3 个最影响当前研究推进的问题，为每个问题形成检索简表：问题 ID、所属领域与阶段、需要补足的知识或证据/方法、对象与机制、术语及替代表达、明确的范围限制、拟用来源与时间窗。方向优先级依据用户目标和实际卡点；对话量不直接转成权重，入门阶段也不等于低优先级。

将用户自然语言反馈原话、原始消息 ID、日期和来源单独保存为 `feedback` 事件。区分论文/问题/项目/全局作用范围；暂时需求保留其时间条件。“这周”“下周”按原消息日期及当地时区解释，不能按本次运行日期自动顺延；缺少原始时间时保留歧义，不作为持续硬过滤。优先级变化与永久排除不是同一件事。不明确的反馈保留歧义，不能推断成长期硬过滤条件。同范围的后续明确反馈更新实际决策，历史原话仍保留。

不要求星级或逐篇评价。没有反馈、未读、没时间、全文难取，均不能自动解释为不感兴趣。旧评分工具仅在调用方配置允许且数据可读时作为补充来源，保持只读；不能宣称其自由备注已被自动学习。

每次独立制定并执行两个检索计划，不以“新文不足”为启动核心检索的条件：

- **方向核心文献（`core`）**：不限定发表年份，围绕当前问题和领域阶段寻找综述、经典理论、代表性原始研究、方法、参数或验证依据；新发表文章同样可以入选。即使近期候选已经足够，也须执行这个不限年份的检索。
- **最新研究进展（`latest`）**：首次优先检索近 14 天新发表或首次上线的论文，之后从最新进展这条检索最近一次完整成功的覆盖终点继续；无可核实终点时说明依据并使用明确回看窗口。按实际在线/发表/预印本首次发布日期核对，数据库新收录旧文不算新发表，预印本修订不等于首次发布。

分别记录两条检索的实际时间范围、来源、查询与完成状态。部分失败不能作为已完整覆盖的截点。最新进展没有合适文献时可为 0，并照常完成不限年份的核心检索；早期文章按核心文献用途展示，不伪装成近期新文。

## 3. 调用现有检索 Skill 并与历史去重

从配置的 `search_skill_path` 读取现有检索 Skill；未配置时在当前 Codex 技能目录寻找 `nature-academic-search/SKILL.md`。按其真实路由加载 `manifest.yaml`、`always_load` 核心文件及 `multi-source-search` 对应工作流，再执行。不要复制旧工具名或凭记忆跳过路由；实际可调用工具以运行时清单为准。缺少该依赖时保存已完成的状态更新并报告检索未完成。

按学科选择来源，独立来源可并行；按依赖 Skill 的规则扩展或降级。记录实际成功、失败的来源和检索式。单一索引检索后打开 DOI 页面，可核实书目信息，但不能写成多个数据库独立检索。常规推荐不自动扩展为严格他引审计、引用文件导出或 Nature/CNS 限刊检索。

对照当前批次、历史记录及实际可读的旧推荐记录去重：

- DOI 去前缀并规范大小写；arXiv 去 URL 包装和版本后缀，同时保留原始版本信息。
- 原始 DOI、arXiv、出版商页面等可作为同一工作的别名；仅在来源明确关联时建立版本族 `work_family_id`。题名相近只触发人工核对，不能据此自动合并。
- 预印本与正式版优先展示适用的正式版。已推荐工作的新版、重要修正，或对新问题有明显新用途时可以再次推荐，但写明前次记录与本次理由。两类清单跨类去重；同时符合核心与最新的文章只展示和计数一次，可在核心栏目注明“兼属最新进展”，并用 `tracks` 保存双重归属。
- 对每篇分别核对书目信息和科学内容。元数据、摘要、全文的证据层级分别记录；只读摘要不能声称核实了全文公式、数据或适用条件。

## 4. 说明推荐价值

分为“方向核心文献”和“最新研究进展”两个栏目。默认全体方向合计核心 **5–10 篇**、最新 **0–3 篇**；核心数量是有足够合格结果时的目标范围，不能降低相关性或用重复文章凑满下限。每领域不单独分配这套数量。分配依据研究优先级和领域学习需要，不保证平均分配。

“核心”不等于旧文，“最新”不等于高价值；两类分别执行检索并按唯一论文计数。“探索”可作为阅读用途标签，不再充当第二个固定推荐栏目。旧的重点/探索配额由双类配置替代。以对当前问题的实际作用排序，不以期刊声望或引用数替代相关性；最新栏目为空时明确说明。

开头简短说明各涉及领域的阶段判断、证据日期与本周阅读目的。逐篇提供题名、作者、年份、发表/预印本状态、DOI 或原文链接；对应问题和领域；阅读用途；必要前置知识；建议精读或浏览及阅读顺序；可能借鉴的方法或证据；适用条件与尚未核实项。最后明确先读的 1–2 篇及两条检索各自的实际覆盖与不足。建议是可行性判断，不能写成已确认能解决用户问题。

## 5. 保留记录并交付

使用记录助手追加新研究快照、反馈和推荐运行，具体字段见 [记录与配置](references/records.md)。每篇保留稳定标识与验证过的别名、问题/领域 ID、唯一展示栏目与双重归属、阅读用途、前置知识、阅读优先级、证据层级、来源、推荐理由及未核实项；运行保存两条检索各自的时间范围、实际来源、完成状态、限制和可复用的完整报告。领域深度画像随研究状态快照保存。

同一周的定时运行使用稳定 ID `weekly:YYYY-MM-DD`（当地周一日期）。重试时若已经存在该运行，读取并复用保存的报告；不能换一个时间 ID 悄悄生成第二批。用户明确要求追加检索时使用新的 `manual:` ID。反馈按原始聊天和消息 ID 去重，不重复累加为新证据。

记录助手整批校验、幂等追加并原子保存；冲突、损坏或无权限时保留现有文件，报告保存未完成，不能重置历史或声称已记住。`complete/partial/failed` 描述检索完成情况，不代表通知已送达。只有准备好向调用方指定聊天交付的结果才记为该次推荐；完整报告留存可供中断后恢复。

记录保存成功后在指定聊天交付结果及记录位置。用户可选用一句“这篇有用/不相关＋原因”反馈，无需逐篇打分；无反馈也正常执行后续运行。
