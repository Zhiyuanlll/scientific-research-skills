# 科研工作流搭建

把科研问题变成可以逐阶段检验、恢复和追溯的计算流程。交付可运行的最小闭环及与其一致的接口和证据；若用户只要求设计，则交付设计，不擅自扩展为计算或软件开发。

本技能不依赖其他 skill、特定 MCP 服务、调度器或 HEA 代码。HEA 是方法案例，不是所有研究的固定结构。中文默认交付，遵循项目语言和用户要求。

## 先确定当前任务

- **从零搭建**：从问题、数据和已有求解器确定证据链，先建立一个能验证的代表性算例，再扩展任务矩阵。
- **整理或重构**：先追踪真实入口、数据依赖、输出和现有运行；保留已验证行为，列出缺口后做最小必要改动。
- **扩展模型或加速**：先确定变化会影响哪些物理定义、数值结果和既有数据，再设计对照与迁移。读取 [变更与结果溯源](references/change-and-provenance.md)。
- **只做审计或分享**：检查接口、证据、可恢复性和环境依赖，交付差异或脱敏包；不因发现问题自动重算。

已有项目优先复用其组织方式和工具。小流程可用一个脚本和一份简短约定，不强制建立框架、三模块、数据库或调度服务。

## 1. 从研究主张倒推证据

读取实际材料，区分：要解释的科学问题、观测或模拟数据、模型假设、数值实现、待检验预测。先形成“问题 → 所需证据 → 计算/对照 → 接受条件 → 图表或结论”的链条。

事实标注实际来源及适用版本。已有文件或日志不等于已完成，程序能运行不等于模型有效，代理模型或合成场不等于独立验证。缺少关键输入时列明缺口，先完成不受影响的设计或实现；不要编造材料参数、误差阈值、实验数据或验证结果。

科研阈值由领域依据、项目约定或用户提供；尚无依据时写为待确定，并给出校准方法。未通过检验、异常数据、审查范围和例外保留在记录中。

## 2. 划分阶段并固定接口

阅读 [阶段与验证约定](references/stage-contracts.md)。依赖图围绕真实数据生产和消费关系建立；内部迭代可在阶段中运行，阶段依赖图中的环需拆开或显式封装成迭代求解器。

每个阶段明确：输入及来源、输出及字段/单位、坐标与符号、活动模型选项、随机性、可执行验收、失败状态与下游消费者。输入提取、模型验证、预测探索可以分开，但模块数量以研究需要为准。

使用稳定的阶段、算例和运行 ID。把物理参数、数值参数、调度资源分开记录；完整配置保留，计算复用依据应覆盖实际影响结果的字段及源代码/输入版本，不能仅凭文件名或 seed。

需要落地文件时，按项目规模选用 [工作流约定模板](assets/workflow-contract.md)、[机器可读阶段模板](assets/workflow-spec.json)；替换示例名称并保留未知量的真实状态，不把模板算例当运行结果。

## 3. 打通最小闭环并设置验证关口

选择能检验主要失效风险的小算例，完成“输入 → 求解 → 定量比较 → 汇总 → 一个可追溯图件”。如果已有闭环，只补当前变更影响的检查。

验证分清四个层次：

- 接口和实现：形状、单位、映射、能量/力一致性、约束或守恒等与当前算法相关的不变量。
- 数值可靠性：网格、步长、容差、域尺寸、初态等必要的收敛或敏感性检查。
- 模型可信度：独立参考或预留验证数据上的误差与适用范围；拟合数据回代作为拟合检查。
- 科学解释：对照是否改变了多个因素、样本是否独立、证据是否足以支持机制判断。

按当前研究选择必要检查，不机械执行所有项目。不以图像相似代替定量验证。配对对照记录共享随机实现和被改变的量；无法配对时说明设计及统计处理。

在验收条件、代表性结果和资源开销清楚后，再启动已授权范围内的批量计算。长计算先给出小试结果、任务数量、预计资源依据和停止条件；用户已授权的批次继续执行，不新增重复确认环节。

## 4. 让运行可以恢复和扩展

涉及批量、长任务、并行或恢复时，读取 [可靠运行](references/reliable-execution.md)。计算只写自己的任务目录，共享汇总由明确的聚合步骤生成。

`planned / running / complete / partial / failed / stale` 是可采用的状态词；已有项目可保留等价语义。完成必须满足科学及数值验收和必需产物，进程退出成功或文件存在均不足。作图失败可单独恢复；求解未收敛不得标完成。

恢复前核对配置、源代码/算法版本、上游输入、随机实现与检查点布局的兼容性。复用兼容且已完成的阶段产物；未完成求解可从兼容且一致的检查点继续，保留旧尝试和失败原因。缺失样本、删失值和部分结果单独汇总，不能填零、重排索引或包装成完整生产结果。

## 5. 管理变更并连接论文证据

涉及模型定义、求解器、接口、性能或论文图件的变更时，读取 [变更与结果溯源](references/change-and-provenance.md)。先识别受影响的阶段及下游，再区分重算、重分析、重绘和仅更新说明；不因一个下游绘图故障重跑全部上游。

每个正式图表保留数值来源、算例/运行 ID、活动配置、代码版本、筛选与聚合规则、样本数及状态，可使用 [图件来源表](assets/figure-provenance.csv)。文字主张跟随实际验证结果，计划图和占位图保持计划身份。正式论文中直接写研究内容，作者讨论、实施安排和运行进度放在项目记录。

## 按需使用审计助手

当项目采用上述 JSON 模板时，可执行标准库助手：

```text
python3 <skill_dir>/scripts/audit_workflow.py --spec <project>/workflow-spec.json
python3 <skill_dir>/scripts/audit_workflow.py --spec <project>/workflow-spec.json --runs <project>/run-records.json --root <project>
python3 <skill_dir>/scripts/audit_workflow.py --spec <project>/workflow-spec.json --changed-stage <stage_id>
```

路径换成实际路径。字段、状态及返回值见 [审计格式说明](references/audit-format.md)；[运行记录模板](assets/run-records.json) 是未执行的计划记录。

助手只读检查依赖图、所提供记录的验收声明、上游关系和文件 SHA-256，并计算受变更影响的候选阶段。它不执行求解或科学检验，不证明阈值合理，不验证整个任务矩阵覆盖，也不自动修改状态；已有格式无需为用该脚本而迁移。

## HEA 案例与交付

用户需要具体示例或从 HEA 经验迁移时，读取 [HEA 案例](references/hea-case.md)。其中的物理定义、版本区分和验证边界仅适用于相应研究，不能复制成通用默认值。

交付与请求范围相匹配：实际入口与配置、必要的阶段/验证约定、已运行检查及结果、未通过项、可恢复位置和剩余限制。设计稿明确标为设计；分享包仅包含可复用指令、模板和代码，排除个人聊天、密钥、机器路径、私有数据和运行历史。修改既有项目时说明哪些结果受影响、哪些可保留及依据。
