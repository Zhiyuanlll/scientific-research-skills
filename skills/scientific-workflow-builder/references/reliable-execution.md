# 可靠运行、恢复与并行

## 先列任务，再调度

一个任务通常由阶段、模型/材料、物理尺寸、随机样本和机制通道确定。先生成稳定任务清单及预期数量，明确哪些组合不适用和哪些依赖共享基线。不要由找到的输出文件反推预期任务数，否则丢失任务会悄悄消失。

每个任务拥有独立输出目录、日志、配置快照和完成记录。并发任务不能共同改写同一个 CSV/JSON 汇总；使用独立记录后单写者聚合，或项目已有的事务存储。

不要修改运行任务正在读取的求解器、生成器或配置。新策略采用独立快照和输出命名空间；若用户要求迁移正在运行的批次，保留已完成数据和中断记录，逐任务记录新旧策略，不能把混合容差批次写成统一容差。

## 状态语义

| 状态 | 含义与允许操作 |
|---|---|
| planned | 已定义，尚无执行结果 |
| running | 已启动，有进度或心跳证据，尚不能被正式聚合 |
| complete | 必需输出可读且通过事先约定的数值/科学验收 |
| partial | 只完成明确子集或有未通过点；仅用于标注清楚的诊断 |
| failed | 当前尝试未满足完成条件；保留可恢复检查点和原因 |
| stale | 原先完成，但相关输入/算法/约定变化后不再兼容 |

`complete` 不等于科学真理，只表示通过已记录范围内的验收。`exit_code=0`、文件大小非零和图件存在是技术检查，均不能单独生成 complete。

## 检查点与恢复

检查点按求解器实际状态设计，可包括迭代变量、路径/加载历史、随机生成器状态、约束状态和最后已提交索引。只保存最终标量不足以恢复需要完整场的诊断或求解。

提交采用项目适合的原子替换或事务；追加数据时保证完成标记在对应数据持久化后写入。中断后识别最后一致检查点，重复提交应幂等或明确生成新的尝试。

恢复前核对输入内容、相关参数、代码/算法版本、网格与状态布局、随机规则和约束。配置不兼容时保留旧记录，为新运行使用新位置；不能简单删掉检查点再写“已恢复”。

分开计算完成、后处理完成、图件完成和交付完成。例如求解通过而绘图失败时复用数值数据重绘，不把绘图失败解释为求解失败，也不声称图已生成。

## 部分结果与删失

正式完整聚合需核对预期任务清单、每项完成状态、协议兼容性和样本独立单位。允许使用有效子集时明确选择规则、缺失原因、有效/预期数量、误差估计及选择偏差，保持 partial 身份。

扫描上限未触发事件的结果是删失或界限，不能将上限写成事件阈值。未收敛点不能按零处理。在带物理坐标/周期滞后量的序列中，删除坏点不能让原先不相邻的点变成相邻；增量、相关和 bootstrap 需保留原网格及有效对掩码。

## 资源分配

按可用 CPU、内存、GPU 和外部许可证约束并发，而非只按逻辑核数。区分多进程任务并行与单任务线程并行，设置底层 BLAS/FFT 线程，防止嵌套超额分配。线程配置是资源请求，不保证实际加速。

小任务通常适合多任务并发，大数组可能适合每任务更多线程；用同一代表算例的时间、峰值内存和结果误差决定。资源立即回收的队列有助于减少空闲，但依赖顺序和聚合关口保持不变。不照搬 HEA 案例中的核数或调度比例。

性能变更比较相同输入、seed、网格、阈值和加载/路径协议。分别报告数值差异与耗时；并行分支未通过比较前保持独立。对系统性调度变化仅重复受影响的验证，不无限扩展检查。
