# 变更影响与结果溯源

## 确定变化属于哪里

| 变化 | 典型影响 | 需要的证据 |
|---|---|---|
| 图题、字体、布局 | 图件与说明 | 原数值不变、图源映射正确 |
| 单位换算、筛选、聚合 | 表、图及相关解释 | 原始数据仍可用；规则与样本数量可追溯 |
| 参考态、物理量定义、场构造 | 本阶段及消费它的下游 | 新旧定义说明与必要重算 |
| 约束、能量、力、容差、扫描协议 | 求解结果、派生指标及验证 | 同条件对照和收敛/接受标准 |
| 并行后端或计算顺序 | 数值差异、恢复兼容性、性能 | 代表性同条件等价性检查 |
| 新增独立派生阶段 | 新输出及其解释 | 上游内容未变及新阶段验证 |

先以依赖图计算受影响候选集合，再逐项判断是否消费了变化字段。候选不代表一律重算；证明未消费变化字段的产物可保留。不能反向把下游变化解释为所有上游失效。

在改动记录中写明：变更原因、受影响定义、版本/配置差异、重算/重分析/重绘清单、保留清单及依据、当前运行是否受影响。重算授权范围之外的工作列为待执行，不制造已完成记录。

## 结果身份与迁移

版本号只能定位一类实现，实际产物需要确切代码快照或提交及未提交差异、配置、上游输入指纹和运行状态。Git commit 在工作区有修改时不足以表示运行代码。非 Git 项目可保留源文件快照及内容散列。

合并多版本或多协议数据前检查物理定义、采样、容差、归一化、终止条件及输出 schema。仅文件字段同名不能证明兼容。无法统一时分组展示并解释，不悄悄重命名为同一生产系列。

改变字段名称时提供映射；改变字段含义时使用新 schema 或新字段并记录迁移。保留旧输出以供复查。字段兼容别名不能被当作两个独立测量值。

## 结论、图件与数据的链接

每个主要主张对应到实际完成的证据：

```text
claim_id → figure/table panel → analysis/plot recipe
         → accepted run_ids → config/code/input fingerprints
         → raw source or upstream runs
```

图件来源表至少保存所用物理量定义、数值表/运行 ID、聚合和筛选、独立样本数、状态与未覆盖范围。布局示意图可标 schematic；合成场、模型扫描和独立验证分别标注。

论文中若引用未生成图件，先判断是排版占位还是计算未完成，不能据 TeX 路径生成“已有结果”的叙述。论文解释与活动实现不一致时记录冲突，核查实际运行后同步公式、图注和结论。

正式稿直接陈述研究对象、方法、证据和适用范围。项目计划、讨论中的提醒、运行安排和纠偏历史放在工作记录。必要纠偏转为科学定义或条件，同时保留未通过检验、不同量的区别和未验证范围；中英文实质内容一致。

## 分享与移植

提取通用约定及脱敏案例，保留字段、算法依赖、验证边界和失败模式。将个人路径改成相对于配置指定项目根目录的路径；接收者自行指定运行位置、计算资源和数据源。

分享源代码、示例配置和说明，不打包凭据、登录状态、私人聊天、项目私有结果、机器环境全集或不明确可分发的原文材料。保留第三方许可证与来源说明，不为原材料推断许可。

分享版若不包含求解器、势函数或原始数据，要明确哪些命令只能作为接口示例。HEA 案例展示方法，不能让接收者误以为安装本 skill 就获得可运行的 HEA 数值软件。
