# 科研周回顾与计划

一个 Skill、两种模式：`review` 回顾本周，`plan` 安排本周/下周。调用方指定模式、时间、交付聊天和 `runtime_dir`；调度器管理日程，本 Skill 不另建任务。未指定模式时按用户意图判断，不能把“写计划”执行为实际科研计算。

读取 `runtime_dir/config.json`，以及配置中的最新研究状态、历史周报和文献推荐记录。持久文件格式及命名见 [报告与状态约定](references/reports.md)。状态与个人路径放在运行目录，不写死在本 Skill。

## 共同的证据工作

1. 从周总结/周计划/文献推荐聊天定位近期信息，再按需发现相关科研聊天和明确关联的项目材料。默认近 7 天，必要时追溯到最近有证据的状态。标题、对话次数、文件修改时间只用于发现材料。
2. 围绕研究问题整理四条线：**文献与知识补足、关键计算、科学结论、方法推进**。保留来源日期和原始证据，区分用户报告、已核查结果、推断与计划。自动周报和助手“将要做”的描述不能自行证明完成。
3. 对关键计算记录目的、代码/方法版本、输入与配置、材料/条件、网格或步长、样本/seed、实际状态、关键数值及单位、验证标准和结果文件。只摘录实际可读、与结论必要的信息；不可读项标明未知。区分排队、运行中、部分完成、失败、数值完成但尚未验证。绘图失败不自动等于计算失败，文件存在不自动等于验证通过。
4. 对科学结论说明支持它的计算/图/文献、适用条件、未通过的检验和不确定性；不能把数值收敛当成物理正确。用户报告与计算摘要冲突时分列证据并标记待核实，不擅自把一方覆盖为已确认事实。区分原始证据日期、本次读取核对时间与实际科学验证时间；日期未知就保留未知。新增证据推翻旧判断时标明变更及日期，保留历史。对方法推进说明新定义、假设、推导/实现/验证分别到哪一步、相对旧方法的变化，以及哪些旧结果仍可用或需要重验；不擅自改写生产配置或重跑计算。
5. 读取文献推荐的两类清单和用户原话反馈，将“推荐→阅读/理解→方法借鉴→实际尝试→验证/否定”的状态分开。仅推荐过不代表已读、已采用或已验证。必要时为方法或结论标注对应论文、证据层级及待核对条件；周报本身不另开一轮检索任务。
6. 按领域保留独立的知识基础与研究深度，不由聊天量或推送次数升级阶段。HEA/PN 等已有项目如需追溯阶段和字段语义，按需读取项目的 `paper-workflow` 等约定；新领域以其自身材料为准，不能套用旧项目的模型假设。

## review：周工作总结

按配置时区，以本周一 00:00 至本次运行时刻为范围。读取上一次已存在的计划，逐项标为完成、部分完成、未开始、失败或证据不足，并给出依据，不虚构百分比。

完整报告包含：本周研究主线；关键计算及验证结果；主要结论与证据边界；方法推进；文献如何影响问题/方法/解释；未完成事项和卡点；需要下周衔接的工作。表格适合承载并行计算和证据对照，不能用只有文件链接的清单代替实质总结。

生成带来源和核实日期的 `current_state.json`，保留项目/问题、关键结果、方法版本、卡点、领域画像和下一步建议，并将完整状态快照放进本次报告目录。仅 `review` 更新共享状态；`plan` 和文献任务只读该文件，避免同时写入。无新证据的方向保留旧核实日期，说明本周未发现可核实进展，不断言用户没有开展工作。

## plan：科研工作计划

周一任务计划本周一至周日；用户明确要求下周时按其指定区间。读取最近成功交付的周总结、共享状态、上次计划和最新用户要求，核对仍未解决的关键依赖。

默认最多 3 项核心目标和 2 项有余力再做的事项。每项写清具体问题、建议行动、关键计算/推导/验证步骤、必要文献或前置知识、预期交付物、可核查完成判据、依赖与主要不确定性。安排周初/周中/周末的建议顺序，不凭空设定用户工时、外部截止日期或完成承诺。

与同为周一运行的文献推荐独立：使用截至运行时已存在的推荐、反馈和状态；本次新推荐未完成就标为后续可纳入，不等待、不假设已经读到。需要用户选择的事项集中列出，其余先提供明确假设下的可执行计划。报告不触发实际计算、提交任务、修改论文或给其他聊天发消息。

## 交付：短概括＋完整报告

- 在指定聊天先给约 150–300 字的概括：主要进展/本周重点、关键结论或卡点、最重要的下一步。随后给出完整 `.md` 报告链接；如有关键图可预览 1 张，并提供 HTML 伴随版。
- 完整报告使用中文。关键推导/定义用 LaTeX 的 `$...$`、`$$...$$` 等数学定界符编写，变量、单位、条件和符号沿用来源；不要把公式放进代码围栏当作最终展示。
- 用 `scripts/render_report.py` 将源 Markdown 的公式实际排版为可见图件并嵌入交付 `.md`，同时保留原生数学 `.source.md` 和公式 PDF/PNG。这样不依赖阅读器是否支持数学扩展；不能以源代码存在代替渲染成功。需要时生成包含公式和图像的自包含 HTML，文件仍保留本地 Markdown 版。
- 引用已有关键图时，优先用可追溯的正式/已核实图件。确需重绘、且有完整数据时调用 `nature-figure`，按配置的论文样式 profile 与对应样图执行；只在图能支持关键结论时绘制，不为每周凑图。数据、图或字体缺失时说明具体缺口，不造数或静默换字体。
- 图在 `.md` 中实际嵌入，并有独立可读的图注；必要时保留 PNG 预览、PDF/SVG 和脚本/数据/QA。正式科学图的尺寸、字体、线型、配色由项目样式和对应原图决定，不套用通用 Nature 字体/尺寸覆盖个人论文规范。
- 保存前核对数字与单位、公式是否成功渲染、图片数量与文件存在、原生公式源是否保留、结论与证据状态是否一致。来源和详细路径记录在证据附件中；图内和图注不混入运行进度、私有路径或助手讨论。

同一周同一模式的重试复用报告目录并核对已有完整输出；更新时保留源文件和已有状态历史。只维护本 Skill 的报告与状态文件，不覆盖科研原始数据或将临时演示写成真实科研进展。保存/渲染部分失败时仍交付能核实的文字部分，并明确尚未完成的输出，不能报告全部成功。
