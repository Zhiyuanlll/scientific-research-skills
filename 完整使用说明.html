科研全流程 Skill 分享包

这套工具集包含 22 个技能，支持从理解研究背景、文献推荐与精读、知识沉淀、研究问题与证据计划，到工作流搭建、统计绘图、论文写作、投稿返修和科研回顾的完整流程。

知识库将文献与研究认识沉淀为可复用的理论、方法和方向证据；周回顾与计划贯穿各研究阶段，核对真实进展、维护研究状态并衔接后续工作。每项技能可以独立按需使用，也可通过来源记录和交付物协作。

建议按以下顺序阅读：

  1. 整体科研流程：主线、周期反馈、交接产物及完整研究示例。
  2. 安装与首次使用：完整或按需安装、更新、验证与调用。
  3. 技能功能与使用示例：按科研流程介绍 22 项能力及操作示例。
  4. 研究状态与周期协同：推荐配置、知识维护、周回顾与计划、资料交接和日程安排。
  5. 依赖与常见问题：检索、下载、绘图、知识库审计、周报公式和 HTML 等依赖。
  6. 打包与验证记录：文件快照、分享版适配和实际检查范围。

也可用浏览器离线打开 完整使用说明.html。

解压后，在包根目录运行：

python3 verify_package.py
python3 install_skills.py --dry-run
python3 install_skills.py

默认目标为 ~/.agents/skills/，可用 --target 指定实际技能目录，--only 按需选择并带上包内依赖。不同内容的同名技能不会被覆盖。Windows 可按本机 Python 安装将 python3 换成 py -3。

安装技能不等于安装外部工具、接入数据库或建立定时任务。所有技能目录应完整保留；研究数据、知识库、周报、推荐记录、访问权限和计算资源由使用者自行配置。包内不含个人聊天、密钥、机构账号、私人科研结果或 HEA 求解器。

科研全流程：从文献与知识到计算证据和论文

这套 22 项技能围绕同一条研究证据链协作：理解研究现状，获得和消化文献，积累知识，提出可检验问题，组织计算或分析，形成图表与论证，并在持续回顾中修正下一步。使用者提供真实材料、代码、数据和访问权限；各技能的输出成为后续工作的有来源输入。

研究主线

研究目标、已有背景与当前问题
               ↓
文献推荐与检索：方向核心文献 + 最新研究进展
               ↓
全文获取与精读：公式、图表、方法条件与原文定位
               ↓
知识库：公共概念、必要理论、方向证据、限制与未知
               ↓
问题与证据计划：主张 → 对照/计算 → 验收条件
               ↓
科研工作流：阶段接口 → 小试验证 → 批量与恢复
               ↓
统计分析与科研绘图：源表、样本、图件及数据来源
               ↓
论文论证与写作：章节、引用、科学含义、语言与图注
               ↓
预审、数据共享、投稿与返修；按需要制作论文汇报

知识库可随阅读、方法发展和研究结果持续更新，而非只在精读后运行一次。已有成熟知识和程序时，可直接从当前需要的环节开始；不必顺序调用全部技能，也不应让目录结构决定研究论证。

贯穿各阶段的周期反馈

文献阅读、知识变化、关键计算、科学结论、方法推进
                         ↓
周回顾 review：核对证据、完成情况、卡点与变化
                         ↓
有来源的研究状态 + 周计划 plan：目标、依赖与完成判据
                         ↓
调整下一轮推荐、知识深化、研究执行和论文修改
                         ↺

周回顾可发生在研究的任何阶段，不需要等待论文完成。被推荐、已阅读、理解、尝试、验证的状态分开；排队、运行中、部分完成、失败、数值完成与科学验证通过也分开。计划始终保持建议身份，不能作为完成证据。

nature-shared 为写作、润色、阅读和汇报提供公共资料，通常无需单独调用。

相邻技能如何分工

research-context-recommender 决定针对当前研究问题和学习需要该读什么，nature-academic-search 执行检索核实；nature-literature-pipeline 适合按主题评分和归档。可以选择一个固定推荐入口，或明确专题监测与问题推荐的分工及去重范围。

nature-reader 保留原文、图表及定位，knowledge-library-builder 从选定材料凝练跨论文、跨项目的概念与方向知识。知识笔记不能替代全文对照；周报记录进展与变化，也不能替代稳定知识。

scientific-workflow-builder 管接口、验证、运行与证据来源，nature-statistics 检查统计设计和报告，nature-figure 管图件表达。绘图失败不自动要求重算，图形美化不改变数据验收状态。

researchwrite 是 nature-proposal-writer 目录对应的调用名，适合复杂论证规划或重构；nature-writing 负责章节和投稿材料，academic-writing-fidelity 保护科学含义，nature-polishing 修改成熟文字。JMPS 专项仅用于明确的目标期刊任务。

research-weekly-review 的 review 负责更新共享研究状态，plan 读取状态提出安排；推荐技能核对后保存自己的事件，知识库维护记录留在 vault。各自的写入归属和配置见 研究状态与周期协同。

一个贯穿全过程的 HEA 研究示例

假设研究随机合金中的位错钉扎，希望判断随机场模型能否解释原子尺度响应。以下请求展示工作衔接，不代表已经得到科学结论，也不预设参数、容差、样本量或最终发现。

  1. 了解背景并推荐。 “使用 $research-context-recommender，区分我熟悉的位错理论和需要补足的随机场知识，独立检索核心与最新文献，说明先读哪两篇。”
  2. 阅读全文。 “使用 $nature-reader 精读方法论文，保留公式、图表与原文定位，提取模型假设、参数来源和验证条件。”
  3. 凝练知识。 “使用 $knowledge-library-builder，从这些已读材料深化随机场与位错响应方向；公共理论共用，方向条件和相反证据分别解释，不只建立目录。”
  4. 建立验证计划。 “使用 $scientific-workflow-builder，围绕模型是否足以解释响应建立证据链，区分原子输入、独立验证和参数预测。先设计，不启动批量。”
  5. 打通计算闭环。 “在已授权的小试范围内完成输入、求解和定量比较，阈值说明依据，保留未通过项，再根据实际结果和资源组织后续计算。”
  6. 分析并绘图。 “使用 $nature-statistics 核对种子与配对设计，用 $nature-figure 从已验收数据生成图、代码、源表和所需格式，标明样本及来源。”
  7. 组织论文。 “使用 $researchwrite 建立事实、证据表和论证图，再用 $nature-writing 起草 Results 与 Discussion，结论限于实际证据。”
  8. 核验引用与表达。 “广泛相关工作用 $nature-academic-search，需要 CNS 支撑时用 $nature-citation，再用 $nature-ref-verifier 核验。目标为 JMPS 时用专项规范，并检查科学原义。”
  9. 投稿、修订与汇报。 “使用 $nature-reviewer 做预审、$nature-data 写实际共享声明，收到意见后用 $nature-response 对应真实修改，需汇报时用 $nature-paper2ppt。”

在上述任何阶段，每周都可请求：“使用 $research-weekly-review 的 review 模式核对本周文献、计算、结论和方法变化；plan 模式读取最近状态安排下一步。不要运行计划中的研究。”下一轮推荐由这些已核实状态和用户反馈继续，而不是每周从零开始。

全过程的最小证据链

文献保留 DOI、来源日期和阅读层级；知识保留定义、适用条件、来源定位和不同证据；计算保留配置、代码版本、输入指纹及验收状态；图件保留源表、筛选、聚合和样本；论文主张对应实际图表与文献。正式知识和论文直接陈述对象与证据，运行安排、作者讨论和修改过程放在项目记录或周报中。

本包不包含私人科研数据或 HEA 求解器。scientific-workflow-builder/references/hea-case.md 提供搭建方法案例，不能当作已完成结果或当前生产配置。其他研究可替换为自己的采集、分析、独立检验和扩展环节，模块数量与物理定义依实际问题确定。

安装与首次使用

选择安装位置

这是本地技能目录分享包，不是已发布的插件或云端服务，不会自动安装 MCP、数据库授权或定时任务。先解压，保留 skills/ 内各技能的完整目录结构。

按当前 OpenAI Docs：Build skills 的本地发现规则，推荐个人目录 ~/.agents/skills/；项目级目录为 <项目>/.agents/skills/。Windows 原生个人目录对应用户主目录下的 .agents/skills/。独立技能需在支持本地技能的客户端使用，普通网页文件上传不等同于本地安装。

打包者当前环境也使用 ~/.codex/skills/；这是本机已观察到的布局。接收者如已有这个目录且客户端确实从中发现技能，可显式指定；不要同时装到多个发现目录造成同名重复。具体版本识别情况以客户端实际技能列表为准。

方法一：使用随包安装器

需要 Python 3.9 或更新版本。在解压后的包根目录运行。Linux/macOS/WSL 用 python3；Windows 原生可按实际安装换成 py -3。

python3 verify_package.py
python3 install_skills.py --list
python3 install_skills.py --dry-run
python3 install_skills.py

默认安装 22 个目录至 ~/.agents/skills/。安装器先核对分享包文件校验值；相同内容的已安装技能跳过，不同内容的同名技能会使本次安装停止，且在复制前报告。它不覆盖旧版、不修改 Codex 配置、不安装软件包、不创建任务。

指定其他位置或按需安装：

python3 install_skills.py --target /实际项目/.agents/skills
python3 install_skills.py --only research-context-recommender scientific-workflow-builder
python3 install_skills.py --only nature-writing nature-polishing nature-reader
python3 install_skills.py --only researchwrite

--only 接受目录名或调用名，自动包含本包内必需依赖，例如推荐技能带上检索技能，写作技能带上 nature-shared。researchwrite 实际安装目录仍为 nature-proposal-writer。路径有空格时使用引号。

对已验证从旧目录发现技能的环境，可使用：

python3 install_skills.py --target ~/.codex/skills --dry-run

确认位置正确后去掉 --dry-run。Windows 直接指定实际路径，不能照抄 Linux 的 ~ 展开规则。

方法二：手动复制

把 skills/ 内所需目录复制到选定的技能根目录；不要只复制 SKILL.md，不要把包的整个 skills/ 目录嵌套成 skills/skills/。

个人或项目的技能根目录/
  nature-writing/SKILL.md
  nature-shared/SKILL.md
  research-context-recommender/SKILL.md
  nature-academic-search/SKILL.md
  scientific-workflow-builder/SKILL.md
  ...

nature-writing、nature-polishing、nature-reader、nature-paper2ppt 与 nature-shared 保持同级。推荐技能与 nature-academic-search 也应一起安装。

验证安装和调用

按官方文档，Codex 可自动检测技能变化；未出现时重启客户端。打开新聊天，检查技能是否可见。Codex 的显式调用形式可使用 $技能名；CLI/IDE 可用 /skills 或 $ 选择，其他界面按实际选择器使用。见 OpenAI Docs 调用说明。

先做无需外部服务的小任务：

使用 $scientific-workflow-builder，根据我提供的项目说明画出证据链和阶段接口。本次只做设计，不运行新计算。

再测试文本：

使用 $academic-writing-fidelity，检查我粘贴的段落，保留数量、假设、例外和证据强度。

最后再配置检索、下载和定时推荐。技能能被发现、网络检索可用、机构全文访问可用是三个不同的检查结果。

更新与移除

更新前保存接收者自己的同名技能改动，将旧目录移到技能发现根目录之外的备份位置，再安装新版。不要直接用备份目录名留在技能根目录中，否则可能继续被识别。个人研究记录在 runtime_dir，更新技能时保留，勿用示例覆盖。

移除时仅移走本次安装的技能目录；检查其他技能是否还依赖它。安装器不执行卸载、删除记录或修改系统设置。

1. 科研上下文文献推荐：research-context-recommender

结合近期研究、领域深度与自然语言反馈，独立检索方向核心文献和最新进展，保存研究状态、推荐与反馈。

输入：科研材料、个人研究背景、推荐记录目录。

产出：有来源的研究状态、双类清单、阅读顺序、持久记录。

使用 $research-context-recommender。请根据我的研究材料推荐文献：核心不限年份、最新单列；先判断各领域的熟悉程度，并保存记录。

2. 多源学术检索：nature-academic-search

检索、核实与去重文献；支持专题检索、引用分析和严格他引等专门任务。

输入：具体问题、关键词、时间与来源范围。

产出：检索式、书目信息、证据与覆盖限制。

21. 科研周回顾与计划：research-weekly-review

一个技能包含 review 和 plan 两种模式。review 依据实际证据回顾本周，plan 根据最近可核实状态安排本周或下周；写计划不等于运行计算。它不会自行创建日程、重新检索一批文献或给其他聊天发送消息。

典型位置为 <runtime_dir>/reports/<当地ISO周>/review/ 或 plan/，包含原生公式源报告 .source.md、嵌入可视公式的 .md、具备工具时生成的自包含 .html、evidence.json 与必要图件；review 另保留状态快照。首次初始化不预填成果。

运行目录中的 config.json 由接收者记录自己的时区、来源/交付上下文、文献推荐记录位置、项目入口、样式与工具路径。见 config-templates/weekly-review-config.example.json；这是供助手读取的起始配置示例，不是渲染脚本的命令行参数 schema。模板为空不代表已接入任何聊天或定时任务。

只有 review 更新共享 current_state.json，并保留历史；plan 和文献任务只读。周一计划读取截至运行时已存在的材料，不等待同时运行的新推荐。周一应引用上一周已存在的周总结，不能只凭相同周目录猜测对应关系。

公式与图件依赖

源报告使用正常 LaTeX 数学定界符，不将最终公式留在代码围栏。render_report.py 将公式排为本地图片，保留原源文件和公式 PDF/PNG。运行示例：

python3 <技能目录>/scripts/render_report.py --source <报告.source.md> --output <报告.md> --font "Times New Roman"

包含公式时需本地 XeLaTeX、相应 TeX 包、pdftoppm 和实际可用的指定字体。自包含 HTML 额外需要本地 Node 和 marked ESM 模块路径：

python3 <技能目录>/scripts/render_report.py --source <报告.source.md> --output <报告.md> --html <报告.html> --font "实际选定字体" --node <node可执行路径> --marked-module <marked的本地ESM模块路径>

本包不安装或附带 TeX、字体、marked 或 Node。无公式的文字版可单独交付；渲染缺工具或缺字体时保留源文件，明确哪些输出未完成。自定义宏先依据原稿展开或给出已有定义，不能为编译成功删改数学含义。生成文件还需要实际检查，不能把文件存在当视觉验收。

已有关键图优先复用已核实、可追溯图件。确需重绘且数据完整时使用本包 nature-figure，按项目样式与对应样图绘制；没有新关键结果时可以不加新图，不凑图、不造数。报告图片嵌入 .md，保留独立可读图注和源数据/脚本。含绝对路径的 Markdown 图片依赖本地文件位置，换电脑分享单份周报时应连同 assets 一起迁移并检查链接，或使用成功生成的自包含 HTML；不能认为搬动一个 .md 就足够。

研究状态、文献推荐与周期协同

文献推荐的执行规则

research-context-recommender 根据当前问题、领域背景和已有反馈执行以下流程：

  • 每个领域分别判断 entry、orienting、problem_driven、results 或 unknown，不把一个领域的熟悉程度套到其他领域。
  • 每次独立执行两条检索：不限年份的方向核心文献，以及有明确时间窗口的最新研究进展。近期新文足够时也要做核心检索。
  • 默认所有方向合计核心 5–10 篇、最新 0–3 篇；数量是合格论文充分时的目标，不能凑数。两类跨类去重，一篇只展示计数一次。
  • 保留用户自然语言反馈、研究状态、逐领域深度、阅读用途/前置知识/阅读顺序，以及两条检索各自的覆盖。未反馈不表示不感兴趣，已推送不表示已掌握。
  • 记录脚本负责持久化，不会安排时间。时间和交付位置由接收者自己的调度任务决定。

首次配置

先安装 nature-academic-search 并确认检索实际可用，再安装推荐技能。建立自己的 runtime_dir，例如 <项目>/文献推荐记录/，复制 config-templates/recommender-config.example.json 为该目录中的 config.json，填写实际路径和自己的资料来源。

模板的 threads 与 discovery_seeds 为空，search_skill_path 为 null；不是任何人的实际配置。可以先提供研究笔记或项目说明，缺少聊天来源时明确覆盖不足。自动跨聊天发现依赖宿主的 list_threads/read_thread 等能力；外部客户端没有这些工具时不会因此获得权限或历史，请改用可读取的个人材料。

初始化空记录（<技能目录> 与 <记录目录> 替换成真实绝对路径）：

python3 <技能目录>/scripts/record_store.py --store <记录目录>/records.json init
python3 <技能目录>/scripts/record_store.py --store <记录目录>/records.json context

init 不覆盖已有记录。不要向其中预填未经核实的研究结论。格式和可选 domain_background 见技能 references/records.md。脚本使用 fcntl，当前按 Linux/POSIX 环境设计；原生 Windows 不可直接运行，Windows 用户可在配置好对应 Codex/Python 的 WSL 环境使用。macOS 的 POSIX 路径需在自己的环境验证；不承诺跨设备/网络目录同步。

第一次可这样请求：

使用 $research-context-recommender，runtime_dir 为我指定的记录目录。读取我提供的研究资料，先说明各领域阶段判断及其来源；独立检索不限年份的核心文献和近 14 天最新进展。默认核心 5–10 篇、最新 0–3 篇，不凑数，说明先读哪两篇并保存记录。本次不创建定时任务。

如何表达反馈

  • “这篇的模型有用，下次优先找参数怎么测定。”
  • “我熟悉位错理论，但刚进入机器学习势函数，需要先补概念与综述。”
  • “这周先解决边界条件，尺寸效应暂缓。”
  • “这篇已经精读；那篇只是收到，还没读。”

反馈保留原话、来源与日期；临时条件按原日期解释。核心/最新的范围和 domain_background 等配置字段不是打分器，不需要逐篇星级评分。

如何设置自己的定时任务

先手动成功运行一次，再向有调度能力的宿主提出明确请求：

请创建每周一北京时间 09:00 的文献推荐任务，调用 $research-context-recommender。使用我的实际 runtime_dir 和我授权读取的研究资料，在指定的推荐聊天交付。每次独立检索方向核心和最新进展，记录实际覆盖与反馈，不重复创建已有任务。

这是供接收者提出的请求模板，本分享包不会执行它。指定真实时区、周期、资料来源、推荐接收位置和通知偏好。可以选每周简报，或仅在有合格新推荐/异常时通知；按个人偏好配置。没有调度能力的环境按需手动调用，不宣称已经自动运行。

周总结和周计划聊天是可选上下文，不是必须复制的三个固定聊天。没有周总结时用实际研究笔记和已有状态；可以从一次研究资料输入开始，不能读取朋友原账号不可访问的聊天。

与持续文献 pipeline 的区别

上下文推荐以当前科研问题、学习深度和反馈为主；nature-literature-pipeline 适合关键词驱动的候选评分、主题摘要和归档。可选一个固定入口，也可明确分工为专题监测与每周问题推荐，但应共用去重记录或说明记录覆盖，避免重复推送。飞书/Telegram 等外部渠道不随包配置。

资料交接与状态归属

research-context-recommender：面向当前问题推荐与安排阅读
                    ↓
nature-reader：保留原文、图表与定位的全文阅读
                    ↓
knowledge-library-builder：持续凝练可复用知识、理论与证据
                    ↓
scientific-workflow-builder：设计、验证和追溯实际计算
                    ↓
统计/绘图/论文：表达已有证据、形成稿件
                    ↓
research-weekly-review：核对进展、方法变化、卡点与下步计划
                    ↘ 新研究状态和反馈，进入下一轮推荐

知识库跨越周期，记录稳定概念、方法、证据与问题；周报记录一段时间的进展、变化和待办。不要把每周进度机械复制进公共概念，也不要把一段知识笔记当作新的完成证据。

各自保存自己的状态：知识库维护信息留在 vault；推荐事件留在推荐 runtime_dir；周回顾的共享 current_state.json 由 review 单写。指定来源后按需读取，不扫描整台机器，也不互相覆盖状态。

安排周期任务

先手动完成一次，再由接收者明确请求宿主创建日程，例如“周日做 review，周一做 plan，文献推荐读取最近已核实状态”。说明真实时区、资料范围、接收位置和通知偏好。知识库维护若要定时，也需单独提出；安装技能本身不创建任何任务。

多源检索 MCP：接收者自行接入

在独立环境中安装包内提供的需求（按实际技能目录替换路径）：

python3 -m venv .venv-literature

Linux/macOS 激活 .venv-literature/bin/activate，原生 Windows 使用对应 Scripts/Activate.ps1；也可始终调用虚拟环境的 Python 绝对路径。

python -m pip install -r <技能根目录>/nature-academic-search/mcp-server/requirements.txt

然后按客户端实际 MCP 配置方式添加本地 stdio 服务。示例 config-templates/academic-search.mcp.example.toml 只给出配置片段，不是完整 Codex 配置，不要覆盖自己的 config.toml。填入虚拟环境 Python 和服务器脚本的绝对路径，PUBMED_EMAIL 用接收者自己的联系邮箱。

服务器支持 search_papers、get_paper_by_id、get_citation、lookup_mesh 等；默认 CrossRef/PubMed/arXiv，Scopus/ScienceDirect 按需启用，需本人的 pybliometrics/API 配置。密钥和机构授权均由接收者自行配置，包内没有。宿主重连后做实际小查询，再依据成功/失败来源报告覆盖。本次打包未联网运行每个数据库接口，不能承诺服务状态、配额或机构全文可用。

技能还描述 paper-search、Zotero 等可选集成，它们不是已随包安装的连接器。没有工具时遵照真实可用路径降级，保留失败范围。

下载、绘图与文件输出

全文获取先用 OA；出版社 API 需要个人配置及实际全文权限。nature-downloader/data/schools.yaml 为空机构模板；用接收者自己的图书馆资源入口配置。相关 Python 依赖在其 requirements.txt。机构浏览器路线引用的 web-access/CDP 运行时没有包含在本包，缺失时需另接可用浏览器能力，不能声称机构下载已就绪。

Python 绘图常用 numpy、matplotlib，按实际脚本补充 pandas、scipy、seaborn 等；R 使用自身绘图包。只安装自己选择路线需要的依赖。示例资产可用作模板，不得把其数据当作自己的结果。AI 示意图路线需要个人 OpenRouter 配置及明确的生成请求，生成稿不是实验/模拟证据。

阅读/PPT 输出依赖可用的提取、渲染和生成工具。包内不含原论文 PDF、Office 或内置演示/文档插件。缺少 PDF 渲染、PPTX 生成或字体时说明实际限制；不能以一份文字大纲宣称真实 PPTX 已交付。

常见问题

  • 技能找不到： 检查根目录是否正确、是否多套一层 skills、是否存在同名重复；查看 SKILL.md 是否完整，再重启客户端。不要把浏览器上传 ZIP 当作本地安装。
  • researchwrite 没出现： 调用名是 researchwrite，目录是 nature-proposal-writer。安装器接受两者。
  • 只装写作后缺共享文件： nature-shared 与写作/润色/阅读/汇报保持同级；用安装器会带上依赖。
  • 检索工具名与文档不同： 以运行时实际工具为准；仅安装技能不会注册 MCP。不虚构 search_papers 已调用。
  • 文献覆盖过窄： nature-citation 默认 CNS 限刊；广泛专题或相关工作用 nature-academic-search。
  • Windows 推荐脚本报 fcntl： 当前记录助手为 Linux/POSIX，改在配置好的 WSL 环境运行。其他跨平台脚本不代表它也跨平台。
  • 定时推荐没有执行： 检查任务是否真正创建、宿主运行条件、资料权限和检索服务；本包不带任务，也不会导入打包者聊天。
  • 安装器报告同名冲突： 它不会覆盖；将旧版备份到发现目录之外，比较改动再安装。研究记录放 runtime_dir 不动。
  • 包校验失败： 文件可能不完整或已编辑；保留自己的改动，重新解压原 ZIP 校验，不用改写清单掩盖差异。

保留各目录已有来源、作者和许可证声明；不同资源的权利边界以原声明为准，本包没有给所有原材料重新指定统一许可证。
