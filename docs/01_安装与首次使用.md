# 安装与首次使用

## 选择安装位置

这是本地技能目录分享包，不是已发布的插件或云端服务，不会自动安装 MCP、数据库授权或定时任务。先解压，保留 `skills/` 内各技能的完整目录结构。

按当前 [OpenAI Docs：Build skills](https://learn.chatgpt.com/docs/build-skills) 的本地发现规则，推荐个人目录 `~/.agents/skills/`；项目级目录为 `<项目>/.agents/skills/`。Windows 原生个人目录对应用户主目录下的 `.agents/skills/`。独立技能需在支持本地技能的客户端使用，普通网页文件上传不等同于本地安装。

打包者当前环境也使用 `~/.codex/skills/`；这是本机已观察到的布局。接收者如已有这个目录且客户端确实从中发现技能，可显式指定；不要同时装到多个发现目录造成同名重复。具体版本识别情况以客户端实际技能列表为准。

## 方法一：使用随包安装器

需要 Python 3.9 或更新版本。在解压后的包根目录运行。Linux/macOS/WSL 用 `python3`；Windows 原生可按实际安装换成 `py -3`。

```bash
python3 verify_package.py
python3 install_skills.py --list
python3 install_skills.py --dry-run
python3 install_skills.py
```

默认安装 23 个目录至 `~/.agents/skills/`。安装器先核对分享包文件校验值；相同内容的已安装技能跳过，不同内容的同名技能会使本次安装停止，且在复制前报告。它不覆盖旧版、不修改 Codex 配置、不安装软件包、不创建任务。

指定其他位置或按需安装：

```bash
python3 install_skills.py --target /实际项目/.agents/skills
python3 install_skills.py --only research-context-recommender scientific-workflow-builder
python3 install_skills.py --only scientific-workflow-builder computation-queue-runner
python3 install_skills.py --only computation-queue-runner
python3 install_skills.py --only nature-writing nature-polishing nature-reader
python3 install_skills.py --only researchwrite
```

`--only` 接受目录名或调用名，自动包含本包内必需依赖，例如推荐技能带上检索技能，写作技能带上 nature-shared。researchwrite 实际安装目录仍为 nature-proposal-writer。路径有空格时使用引号。

对已验证从旧目录发现技能的环境，可使用：

```bash
python3 install_skills.py --target ~/.codex/skills --dry-run
```

确认位置正确后去掉 `--dry-run`。Windows 直接指定实际路径，不能照抄 Linux 的 `~` 展开规则。

## 方法二：手动复制

把 `skills/` 内所需目录复制到选定的技能根目录；不要只复制 SKILL.md，不要把包的整个 skills/ 目录嵌套成 `skills/skills/`。

```text
个人或项目的技能根目录/
  nature-writing/SKILL.md
  nature-shared/SKILL.md
  research-context-recommender/SKILL.md
  nature-academic-search/SKILL.md
  scientific-workflow-builder/SKILL.md
  computation-queue-runner/SKILL.md
  ...
```

nature-writing、nature-polishing、nature-reader、nature-paper2ppt 与 nature-shared 保持同级。推荐技能与 nature-academic-search 也应一起安装。

## 验证安装和调用

按官方文档，Codex 可自动检测技能变化；未出现时重启客户端。打开新聊天，检查技能是否可见。Codex 的显式调用形式可使用 `$技能名`；CLI/IDE 可用 `/skills` 或 `$` 选择，其他界面按实际选择器使用。见 [OpenAI Docs 调用说明](https://learn.chatgpt.com/docs/build-skills#how-chatgpt-and-codex-use-skills)。

先做无需外部服务的小任务：

> 使用 $scientific-workflow-builder，根据我提供的项目说明画出证据链和阶段接口。本次只做设计，不运行新计算。

再测试文本：

> 使用 $academic-writing-fidelity，检查我粘贴的段落，保留数量、假设、例外和证据强度。

最后再配置检索、下载和定时推荐。技能能被发现、网络检索可用、机构全文访问可用是三个不同的检查结果。

## 首次使用独立计算队列

`computation-queue-runner` 可单独安装，不强制安装工作流技能。它随附的执行器需要 Linux、Python 3.9+、systemd 254+ 和可用的 `systemctl --user`/`systemd-run --user`。其他系统可读技能中的调度适配说明；随附脚本不提供原生 Windows、macOS 或 Slurm 提交后端，也不因安装技能而改变主机设置。

正式科研计算无论长短，包括单个小算例，都交给独立后端执行。用户说明目标与授权范围后，Codex 从项目材料准备任务清单、实际可执行文件、工作目录、输入、线程与内存预算及既定验收命令，并检查后实际提交。开始已授权计算不要求用户手动再提交或进行固定的二次确认；仅要求设计时不运行。语法检查、单元测试和短暂环境检查属于开发检查，不因执行 shell 命令就都成为正式计算。可直接使用：

> 开始这些正式计算。使用 $computation-queue-runner，检查资源和正在运行的计算后实际提交到独立服务，核实服务标识、日志与心跳，关闭 Codex 后队列仍继续；不要重启或接管其他现有任务。

以下是 Codex 可准备并执行的底层命令，也供需要时手动操作。用户无需逐条复制；实际路径由执行者核对。生成的模板应先编辑，不能直接当生产计划：

```bash
python3 /实际技能目录/computation-queue-runner/scripts/durable_queue.py template /实际项目/queue.json
python3 /实际技能目录/computation-queue-runner/scripts/durable_queue.py validate /实际项目/queue.json
python3 /实际技能目录/computation-queue-runner/scripts/durable_queue.py submit /实际项目/queue.json --run-dir /实际项目/queue-run
python3 /实际技能目录/computation-queue-runner/scripts/durable_queue.py status /实际项目/queue-run
```

提交后检查状态、服务和任务进程，确认关闭客户端不会结束它；不能只凭“命令已返回”判断独立运行已建立。若还要求退出用户登录后继续，提交时使用 `--require-linger` 并检查该用户的 linger 实际已启用。脚本不自动启用它。关闭客户端后的持续执行不保证休眠、重启或断电期间计算，恢复要求和检查点格式见该技能自身说明。

## 更新与移除

更新前保存接收者自己的同名技能改动，将旧目录移到技能发现根目录之外的备份位置，再安装新版。不要直接用备份目录名留在技能根目录中，否则可能继续被识别。个人研究记录在 runtime_dir，更新技能时保留，勿用示例覆盖。

移除时仅移走本次安装的技能目录；检查其他技能是否还依赖它。安装器不执行卸载、删除记录或修改系统设置。
