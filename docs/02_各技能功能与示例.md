## 1. 科研上下文文献推荐：research-context-recommender

结合近期研究、领域深度与自然语言反馈，独立检索方向核心文献和最新进展，保存研究状态、推荐与反馈。

输入：科研材料、个人研究背景、推荐记录目录。

产出：有来源的研究状态、双类清单、阅读顺序、持久记录。

> 使用 $research-context-recommender。请根据我的研究材料推荐文献：核心不限年份、最新单列；先判断各领域的熟悉程度，并保存记录。

## 2. 多源学术检索：nature-academic-search

检索、核实与去重文献；支持专题检索、引用分析和严格他引等专门任务。

输入：具体问题、关键词、时间与来源范围。

产出：检索式、书目信息、证据与覆盖限制。

> 使用 $nature-academic-search。请检索这个问题的代表性理论、实验与方法论文，核实 DOI，说明实际检索来源。

## 3. 全文与补充材料获取：nature-downloader

通过合法开放获取、出版商 API 或个人机构访问获取全文及补充材料。

输入：DOI、题名或原文链接。

产出：获取的文件、来源与下载状态。

> 使用 $nature-downloader。请获取这些 DOI 的可用全文和补充材料，记录来源；机构权限使用我自己的访问环境。

## 4. 全文对照阅读：nature-reader

形成图表随文、保留原文定位的中英对照阅读稿，不默认退化为摘要。

输入：可读取 PDF、出版商正文、DOI 或粘贴原文。

产出：对照阅读稿、图表和来源定位。

> 使用 $nature-reader。请将这篇论文做成全文中英对照阅读稿，图表放在相关段落附近并保留来源位置。

## 5. 知识库搭建与方向深化：knowledge-library-builder

它把用户指定的论文阅读稿、研究笔记、方法资料和可核实项目材料，凝练成总知识库、公共概念和有内容的方向专题。可用于 Obsidian Markdown vault，也可使用普通本地 Markdown 文件夹；无需为了使用本技能先安装 Obsidian。

四种模式：build 建立总库，deepen 深化方向，update 归并新证据，audit 只读检查。深化应包含问题边界、理论机制、方法与可观测量、证据限制和未解决问题；建立一批空目录或导航链接不能算完成。

输入是你明确选定的资料、现有库、方向和深度要求。产出是可读的知识笔记、方向入口、来源登记、链接和维护记录。它不替代 nature-reader 的全文对照翻译，也不负责执行笔记中的科研方案。

### 请求示例

> 使用 $knowledge-library-builder 的 build 模式，仅根据我指定的资料建立知识库。先登记来源，将共用理论与各研究问题分开；知识正文解释原理、证据和适用条件，保留缺失证据，不复制运行进度和聊天安排。

> 使用 $knowledge-library-builder 的 deepen 模式，把这个方向深化到研究层级。复用已有公共概念，补足方法选择、必要推导与相反证据，保护我的批注；缺少的资料列为缺口。

> 使用 $knowledge-library-builder 的 update 模式，归并这些新论文和已核实结果。编辑前备份并核对文件是否并发变化，不批量删除或改名来去重。

> 使用 $knowledge-library-builder 的 audit 模式，只读审查这个库的方向内容、来源、链接与重复候选，不修改笔记。

### 随附审计工具

需要 Python 3.10+。核心脚本使用标准库；PyYAML 是可选增强，未安装时会明确报告属性解析限制。

```bash
python3 <技能目录>/scripts/audit_vault.py --vault <实际知识库目录> --report <知识库之外的报告路径.json>
python3 <技能目录>/scripts/smoke_test.py
```

报告必须放在 vault 外。它检查本地 wiki/Markdown 链接、别名、标题或块引用、Canvas、基础属性及完全重复内容候选；不联网验证外链，不判断科学正确性或语义重复，也不自动删除。备份位于库外或明确排除出索引，避免被当成重复知识。

## 6. 科研工作流搭建：scientific-workflow-builder

从研究问题和现有代码构建阶段接口、定量验证、批量运行、恢复与图件溯源。

输入：研究问题、数据、代码及资源约束。

产出：可验证的流程、接口、最小闭环、运行与来源记录。

> 使用 $scientific-workflow-builder。请根据研究问题和代码建立工作流，先打通小算例，明确验证关口，再设计批量与恢复。

## 7. 统计方法与报告：nature-statistics

审查独立样本、统计方法、效应量、不确定性、p 值及图注统计报告。

输入：实验设计、原始/汇总数据、统计方法及结果。

产出：统计审查与可据实使用的报告文字。

> 使用 $nature-statistics。请检查我的重复单位、误差条和统计方法，并区分已完成分析与待补充检查。

## 8. 科研绘图：nature-figure

用 Python 或 R 生成、检查和导出论文图；明确请求时支持 AI 示意图草案。

输入：数据表、物理量定义、图件结论和导出要求。

产出：绘图源代码、图文件、图件检查结果。

> 使用 $nature-figure。请用 Python 根据已验收数据绘制多面板论文图，保留单位、样本数和来源，导出 PDF 与 TIFF。

## 9. 提案优先的科研写作：researchwrite

先建立事实、证据表、论证图和章节约定，再写提案、综述或重构复杂稿件。

输入：研究材料、已有草稿、范围及证据。

产出：论证与证据文件、分节草稿和质量记录。

> 使用 $researchwrite。请先建立证据表和论证结构，再起草这个综述；缺少证据的主张单独列出。

调用名是 researchwrite，不是目录名。外部 professor 等技能未包含，分享版已写明可用工具与明确单代理审查的适配方式。

## 10. 论文起草与投稿材料：nature-writing

起草和重建论文各章节，以及首次投稿的配套材料。

输入：有来源的结果、图件、研究主张与目标期刊。

产出：论文段落/章节与投稿材料。

> 使用 $nature-writing。请根据已完成结果和图件来源表起草 Results，保留模型假设和未验证范围。

## 11. 通用科学写作规范：academic-writing-fidelity

跨期刊保护科学含义、数量、假设和证据强度，保持术语和图注一致。

输入：原文、事实依据及写作目标。

产出：忠于科学含义的正文、图注或语言审查。

> 使用 $academic-writing-fidelity。请审核正文和图注，保留原义、数量、模型条件和证据强度，并清理讨论痕迹。

## 12. 文本配文献与引用导出：nature-citation

分段寻找论述支撑并导出引用；当前默认范围为 Nature/Science/Cell 及所接受子刊。

输入：待引用文字、时间范围与目标格式。

产出：论述—来源对应、支持程度及引用文件。

> 使用 $nature-citation。请为这些论述找 CNS 及子刊的支撑文献，区分直接支持与背景相关，导出 RIS。

当前规则为 CNS/Nature 等指定刊族，不能当作全学科无限刊检索。完整相关工作优先使用 nature-academic-search，不为匹配高影响期刊牺牲直接相关性。

## 13. 参考文献核验：nature-ref-verifier

核对作者、题名、年份、卷期、页码和 DOI，按需要连接个人 Zotero。

输入：参考文献列表、BibTeX 或数据库记录。

产出：字段差异、核实结果和待确认项。

> 使用 $nature-ref-verifier。请逐条核验这份参考文献，保留未核实项，不凭题名猜测 DOI。

## 14. 论文润色与翻译：nature-polishing

以 Nature 倾向的行文组织润色和翻译，按需处理 LaTeX 布局。

输入：已有文字、目标期刊及受保护含义。

产出：润色稿、翻译或布局修订。

> 使用 $nature-polishing。请润色这段 Discussion，保持因果与推断强度，统一正文和图注术语。

## 15. JMPS 写作规范：jmps-writing-fidelity

面向 JMPS/力学论文的专项表达，保留力学定义和证据边界。

输入：JMPS 目标稿或明确指定的力学写作任务。

产出：符合专项规范的稿件和语言审查。

> 使用 $jmps-writing-fidelity。请按 JMPS 风格修改这段力学论述，保留边界条件、近似假设和数量。

## 16. 投稿前模拟审稿：nature-reviewer

从审稿人视角给出三份评估及综合问题清单，依据实际稿件而非假想成果。

输入：完整或部分稿件、图件与补充材料。

产出：审稿报告、证据缺口与修改优先级。

> 使用 $nature-reviewer。请做投稿前模拟审稿，检查创新性、技术论证和证据范围，并定位问题。

三份模拟评估不等于三位真实独立外部审稿人，也不保证录用；以实际阅读范围和来源为限。

## 17. 数据与代码可用性：nature-data

准备数据可用性声明、仓库计划、数据引用和 FAIR 元数据检查。

输入：真实数据/代码位置、共享条件和限制。

产出：可据实使用的声明与共享计划。

> 使用 $nature-data。请根据这些实际共享条件写数据可用性声明，尚无 DOI 的数据不要编造编号。

## 18. 审稿回复与返修：nature-response

将审稿意见对应到实际行动和证据，形成逐点回复、返修信及修订材料。

输入：编辑/审稿意见、实际修改与新增结果。

产出：意见跟踪、逐点回复和修订材料。

> 使用 $nature-response。请逐点整理审稿意见，区分已修改和待完成事项，据实际证据起草回复。

## 19. 论文汇报 PPT：nature-paper2ppt

从论文形成中文汇报故事、图件、讲稿和真实 PPTX，并检查版式。

输入：论文、图表、汇报时长与听众。

产出：PPTX、演讲备注和图件检查。

> 使用 $nature-paper2ppt。请把这篇论文做成中文组会 PPT，保留完整关键图并说明证据与限制。

## 20. 持续文献发现与归档：nature-literature-pipeline

按关键词或专题进行候选筛选、评分、精读、摘要交付和归档；调度与渠道另配置。

输入：研究专题、关键词、评分与归档偏好。

产出：文献摘要、评分依据、阅读笔记和归档。

> 使用 $nature-literature-pipeline。请按这个专题筛选候选文献并归档笔记；本次只在当前聊天交付，不创建定时任务。

## 21. 科研周回顾与计划：research-weekly-review

一个技能包含 review 和 plan 两种模式。review 依据实际证据回顾本周，plan 根据最近可核实状态安排本周或下周；写计划不等于运行计算。它不会自行创建日程、重新检索一批文献或给其他聊天发送消息。

每次围绕四条线整理：文献与知识补足、关键计算、科学结论、方法推进。计算记录目的、版本、输入条件、关键数值/单位、验收与状态；保留未通过项、相反证据、删失与尚未验证范围。排队、运行中、部分完成、失败、数值完成但未验证分别表达。

### 请求示例

> 使用 $research-weekly-review 的 review 模式，runtime_dir 为我指定的运行目录。按配置时区回顾本周，核对上次计划，衔接文献、关键计算、结论和方法变化。先给简短概括，再保存完整 Markdown、证据附件和研究状态；本次不执行科研任务。

> 使用 $research-weekly-review 的 plan 模式，根据最近成功交付的周回顾、研究状态和最新用户要求安排下周。默认最多 3 项核心目标和 2 项有余力再做的事项，写清完成判据和依赖，不虚构工时或截止日期，不更新共享研究状态。

### 输出与运行目录

典型位置为 `<runtime_dir>/reports/<当地ISO周>/review/` 或 `plan/`，包含原生公式源报告 `.source.md`、嵌入可视公式的 `.md`、具备工具时生成的自包含 `.html`、evidence.json 与必要图件；review 另保留状态快照。首次初始化不预填成果。

运行目录中的 config.json 由接收者记录自己的时区、来源/交付上下文、文献推荐记录位置、项目入口、样式与工具路径。见 config-templates/weekly-review-config.example.json；这是供助手读取的起始配置示例，不是渲染脚本的命令行参数 schema。模板为空不代表已接入任何聊天或定时任务。

只有 review 更新共享 current_state.json，并保留历史；plan 和文献任务只读。周一计划读取截至运行时已存在的材料，不等待同时运行的新推荐。周一应引用上一周已存在的周总结，不能只凭相同周目录猜测对应关系。

### 公式与图件依赖

源报告使用正常 LaTeX 数学定界符，不将最终公式留在代码围栏。render_report.py 将公式排为本地图片，保留原源文件和公式 PDF/PNG。运行示例：

```bash
python3 <技能目录>/scripts/render_report.py --source <报告.source.md> --output <报告.md> --font "Times New Roman"
```

包含公式时需本地 XeLaTeX、相应 TeX 包、pdftoppm 和实际可用的指定字体。自包含 HTML 额外需要本地 Node 和 marked ESM 模块路径：

```bash
python3 <技能目录>/scripts/render_report.py --source <报告.source.md> --output <报告.md> --html <报告.html> --font "实际选定字体" --node <node可执行路径> --marked-module <marked的本地ESM模块路径>
```

本包不安装或附带 TeX、字体、marked 或 Node。无公式的文字版可单独交付；渲染缺工具或缺字体时保留源文件，明确哪些输出未完成。自定义宏先依据原稿展开或给出已有定义，不能为编译成功删改数学含义。生成文件还需要实际检查，不能把文件存在当视觉验收。

已有关键图优先复用已核实、可追溯图件。确需重绘且数据完整时使用本包 nature-figure，按项目样式与对应样图绘制；没有新关键结果时可以不加新图，不凑图、不造数。报告图片嵌入 `.md`，保留独立可读图注和源数据/脚本。含绝对路径的 Markdown 图片依赖本地文件位置，换电脑分享单份周报时应连同 assets 一起迁移并检查链接，或使用成功生成的自包含 HTML；不能认为搬动一个 `.md` 就足够。

## 22. 共享规则与资料：nature-shared

为写作、润色、阅读和汇报技能提供术语、证据、行文与期刊规则。

输入：由依赖它的技能按需读取。

产出：共享规范，通常不单独生成交付物。

通常无需单独调用。由依赖它的技能按需加载。
